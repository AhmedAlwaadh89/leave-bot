# نظام إدارة الإجازات عبر تيليجرام

هذا المشروع يهدف إلى بناء نظام لإدارة إجازات الموظفين باستخدام بوت تيليجرام. يمكن للموظفين تقديم طلبات الإجازة، والاستعلام عن رصيد الإجازات، وتلقي إشعارات بحالة طلباتهم. يمكن للمدراء مراجعة الطلبات والموافقة عليها أو رفضها.

## الميزات

- تقديم طلبات الإجازة (يومية، بالساعة، أو بدون راتب) عبر بوت تيليجرام، مع اختيار موظف بديل.
- الاستعلام عن الرصيد وإلغاء الطلبات المعلّقة من البوت.
- إشعارات فورية بحالة الطلبات (مقبولة، مرفوضة، قيد المراجعة، ملغاة) وتحديث رسائل المدراء الآخرين.
- واجهة ويب للمدراء: مراجعة الطلبات، الموافقة/الرفض/التحويل إلى بدون راتب، إدارة الموظفين (إيقاف/تفعيل/حذف) والعطلات، تقارير وتصدير CSV.
- قائمة مدير داخل البوت: مراجعة الطلبات، إدارة الموظفين (موافقة/إيقاف/تفعيل/حذف)، الأرصدة، تقرير Excel.
- تذكير يومي للمدراء بالطلبات المعلّقة أكثر من 24 ساعة.

## سياسة الرصيد

- حصة شهرية لكل موظف: **2 يوم و 4 ساعات** افتراضياً (قابلة للتعديل لكل موظف).
- تتجدد **أول كل شهر بدون تراكم**. ما لم يُستخدم يُسجَّل كملاحظة للإدارة ("غير مستخدم سابقاً") ويُعرض على المدير عند كل طلب جديد لتقدير الحالة.
- **أيام العمل من السبت إلى الخميس**؛ الجمعة والعطلات الرسمية لا تُحسب من الرصيد.
- لا يمكن تقديم طلب يتجاوز الرصيد؛ يُعرض على الموظف تحويله إلى **إجازة بدون راتب** (لا تُخصم من الرصيد) أو تقديم طلب أقصر.

التفاصيل الكاملة في [MONTHLY_RENEWAL_GUIDE.md](MONTHLY_RENEWAL_GUIDE.md).

## التقنيات المستخدمة

- Python 3.11
- `python-telegram-bot`
- Flask + SQLAlchemy
- PostgreSQL في الإنتاج، SQLite محلياً

## التشغيل محلياً (Running Locally)

1. **تثبيت المتطلبات**:
   ```bash
   pip install -r requirements.txt
   ```

2. **إعداد قاعدة البيانات**:
   - سيتم إنشاء قاعدة البيانات تلقائياً عند تشغيل التطبيق لأول مرة.
   - الترحيلات (إضافة الأعمدة الجديدة) تعمل تلقائياً عند التشغيل. لتشغيلها يدوياً:
     ```bash
     python scripts/migrate_db.py
     ```

3. **إعداد متغيرات البيئة**:
   - قم بإنشاء ملف `.env` أو قم بتعيين المتغيرات في التيرمينال:
     ```bash
     set TELEGRAM_BOT_TOKEN=your_token_here
     set FLASK_SECRET_KEY=your_secret_key
     ```

4. **التشغيل**:
   ```bash
   python app.py
   ```
   يشغّل هذا الأمر لوحة الويب والبوت والمجدوِل معاً (يمكن تعطيل البوت داخل الويب بـ `RUN_BOT_IN_WEB=0` وتشغيل `python bot.py` و`python scheduler.py` بشكل منفصل).
   - افتح المتصفح على الرابط: `http://127.0.0.1:5000`
   - بيانات الدخول من `ADMIN_USERNAME` و`ADMIN_PASSWORD` (الافتراضي `admin` / `secret` للتطوير فقط؛ غيّرها في الإنتاج).

5. **الاختبارات**:
   ```bash
   python -m unittest discover -s tests -v
   ```

## النشر (Render)

الخدمة تعمل كعملية ويب واحدة تشغّل لوحة الإدارة والبوت والمجدوِل معاً.

1. أنشئ **Web Service** من هذا المستودع (أو استخدم Blueprint عبر ملف `render.yaml`).
2. أمر التشغيل: `gunicorn --workers 1 --threads 4 --timeout 120 app:app` (موجود في `Procfile`).
3. متغيرات البيئة:
   - `TELEGRAM_BOT_TOKEN`: رمز بوت التليجرام.
   - `DATABASE_URL`: رابط PostgreSQL (Neon أو Render Postgres). بدونه يُستخدم SQLite ويُفقد عند كل نشر.
   - `FLASK_SECRET_KEY`: مفتاح عشوائي طويل.
   - `ADMIN_USERNAME` / `ADMIN_PASSWORD`: بيانات دخول لوحة الإدارة.
4. **Health check path**: `/health`. يعيد حالة قاعدة البيانات والبوت والمجدوِل.
5. **منع النوم على الخطة المجانية**: المجدوِل يستدعي `/health` كل 10 دقائق تلقائياً عبر `RENDER_EXTERNAL_URL`
   الذي توفره Render. يمكن أيضاً إضافة مراقب خارجي مثل UptimeRobot على نفس المسار كطبقة ثانية.

راجع `.env.example` لكل المتغيرات الاختيارية.
